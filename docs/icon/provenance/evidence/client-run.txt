## what the client could and could not do
The session is offline-mode, so the client's chat is restricted ("Chat is restricted", "Sending commands is not
allowed" as recorded in evidence/client-commands.txt). Every camera move was therefore issued from the dedicated
server console with /execute in minecraft:the_end run tp IconCapture <x> <y> <z> facing <tx> <ty> <tz>, and the
client only ever sent F1 (hide HUD), Escape (leave the End poem) and F2 (screenshot).

## the cinematic set (2026-09-17), with the local orthographic mod

command: sh launch.sh under systemd-run --user --scope -p CPUQuota=200% -p CPUWeight=20
display: Xvfb :213 1600x1600x24; audio sink: round3_floodedend (null); window --width 1600 --height 1600
extra mod: /tmp/orthocam/orthocam-1.0.0.jar, on the classpath and in -Dfabric.addMods (source kept in tools/orthocam/)

[Render thread/INFO]: [STDOUT]: ORTHO hook is live (enabled=false distance=64.0)
[Render thread/INFO]: [STDOUT]: ORTHO perspective m=[m00 0.8540808 m11 0.8540808 m22 4.883051E-5 m23 -1.0 m32 0.05000244 m33 0.0]
[Render thread/INFO]: [STDOUT]: ORTHO parallel    m=[m00 0.017793348 m11 0.017793348 m22 4.883051E-5 m23 0.0 m32 0.05000244 m33 0.0]
(the parallel matrix has no divide by depth: m23 = 0, so w' is constant and the projection has no vanishing point)

The same client shot both projections by rewriting /tmp/ortho.cam between frames; the two orthographic frames and
the perspective control are in renders/ and evidence/, and the comparison is evidence/ortho-compare.png.

One run crashed before this (exit 255): the first packaging of the scratch mod put its helper class inside the mixin
package, which Mixin refuses to reference directly. Moving the helper to orthocam.* fixed it and the run above is
the one that produced the delivered frames.
